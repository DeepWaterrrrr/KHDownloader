# KHDownloader —— KHInsider 专辑 MP3 下载器（免安装版）

这是一个**独立可执行程序**（single-file EXE）。它能下载 KHInsider 专辑页上的 MP3，
有图形界面：能看到进度、随时可以取消。

**本程序不需要安装 Python，不需要装任何库。** 双击就能用。

本版修的是一个具体问题：**站点用 Cloudflare 人机校验挡住程序（HTTP 403 +
`cf-mitigated: challenge`），导致"输入专辑 URL 自动下载"这条路线走不通。**
v1.0.0 起程序改用**浏览器网络指纹**发出请求（TLS / HTTP2 指纹与真 Chrome 一致），
被拦时还会自动逐级升级（浏览器 Cookie → 内置真浏览器 → 你本机的浏览器），
所以直接填专辑地址就能下载，不再需要手工另存网页再导入。

> 这不是"破解验证码"：程序只是**用真浏览器的方式去读一张公开专辑页**，
> 不答题、不伪造令牌、不借用别人的会话、不绕过登录或付费。

## 2. 怎么运行

1. 打开本文件夹；
2. **双击 `KHDownloader.exe`** ← 就这一个，文件名不带阶段编号；
3. 稍等片刻（首次启动会解压，约 1~3 秒），窗口就会弹出。

**看不到控制台黑框是正常的** —— 这是图形界面程序。

> 关于"单文件"：每次启动会先把内部文件解压到系统临时目录 `%TEMP%\_MEIxxxxxx`，
> 运行结束自动清理。这是正常行为。

## 3. 怎么用

### 路线一：直接输入 URL

1. 在"专辑地址"框填 KHInsider 专辑页地址，例如
   `https://downloads.khinsider.com/game-soundtracks/album/xxxx`；
2. 点"选择文件夹…"确定保存目录；
3. 点"开始下载"。

程序会自己选一条能过站点校验的路（日志里能看到它停在哪一层）：

| 层 | 做什么 | 什么时候用得上 |
| --- | --- | --- |
| **L1** | 用浏览器指纹（默认 Chrome）发请求 | 绝大多数情况，第一层就成了 |
| **L2** | 程序自己启动一个无头浏览器过一遍校验，把拿到的凭据交回请求层 | 站点要求先执行 JS 才给放行时 |
| **L3** | 直接用无头浏览器渲染出的成品网页 | L2 拿到了页面但请求层仍被拦时 |
| **L4** | 调你**本机装的** Chrome/Edge 跑一次页面，把成品 HTML 交给程序 | 前三层都没过时兜底（EXE 版的主力后备） |

> **L2 / L3 需要 Playwright**（源码版才有，EXE 里没有）；**L4 需要你机器上有 Chrome 或 Edge**
> （通常都有）。所以 EXE 版实际可用的是 **L1 → L4**。
> 这一层里用的浏览器会话**都是程序新开的临时会话**，不读你浏览器的配置、Cookie 和书签。

四层都没过，程序会明确告诉你"被站点人机校验拦住"，并给出下一步（稍后再试 /
换个网络 / 走路线二），**不会**把它混成"没找到曲目"。

### 路线二：导入已保存的网页（仍然保留，作为兜底）

1. 点 **"用浏览器打开"**，在正常浏览器里打开专辑页并通过人机验证；
2. 等曲目列表真正出现，按 `Ctrl+S` 另存为 → 选 **"网页，仅 HTML"**；
   （**不要**选"单个文件 MHTML"，那种格式本程序不支持，改扩展名也没用）
3. 回到程序点 **"导入专辑页面…"**，选刚保存的那个 HTML；
4. 程序会先**识别这份网页属于哪张专辑**，再和地址框里的地址核对：
   - 地址一致 → 直接进入预览；
   - 地址是别的专辑 → 弹出提示并列出两个地址，你选"使用网页中的专辑地址"或取消；
   - 地址为空 → 提示已识别出的地址，确认后回填；
   - 地址填的是单曲详情页 → 提示这是歌曲页，可一键切回专辑地址；
   - 实在认不出来 → 明确说认不出，请你核对，不猜、不启动下载；
5. **预览**里会显示专辑名、确认后的地址、曲目总数、曲目顺序与名称、当前保存目录；
6. 你点"是"才真正开始下载。关闭或取消预览**不会发出任何下载请求**。

### 下载过程中

- "开始下载"变灰、"取消"变亮；
- 专辑进度显示"第几首 / 共几首"和当前曲名；当前文件进度显示这个 MP3 下了多少；
- 主窗口的"来源"会显示 `直接请求` 还是 `已导入网页（<地址>）`；
- 点"取消"会在安全的地方停下，已下好的保留，**不会留下半个文件**；
- 结束后最下面显示汇总：`完成 12 | 跳过 2 | 失败 1 | 取消 0`。

| 计数 | 含义 |
| --- | --- |
| **完成** | 这次真的下载好了 |
| **跳过** | 本地已有同名且大小一致的文件，没重复下 |
| **失败** | 这一首出错了（网络 / 页面 / 写盘等），日志里有原因 |
| **取消** | 你按了取消，这一首没弄完（**不是出错**） |

## 4. 文件安全行为

- **先写临时文件**：每个 MP3 先写成 `曲名.mp3.part`；
- **写全才改名**：确认字节数正确后才原子地改名成 `曲名.mp3`；
- **失败或取消就删掉半成品**；
- **不覆盖已有文件**：同名同大小 → 跳过；同名不同大小 → 自动改成 `曲名 (2).mp3`；
- **只写你选的保存目录**（默认 `%USERPROFILE%\Downloads\KHInsider`），
  外加系统临时目录的解压；不写注册表、不装服务、不加自启动、不回传信息。

`KHDownloader.exe` 带一个蓝色圆角方块 + 白色音符与下载箭头的图标：

## 7. 关于 Cloudflare 校验（v1.0.0 起的变化）

KHInsider 的专辑页在 Cloudflare 后面，对**程序化请求**下发人机校验：请求返回
`HTTP 403` + 响应头 `cf-mitigated: challenge`，页面是一张 `Just a moment...`。

**真正被认出来的是"这不是浏览器"，而不是某个请求头写错了。** 站点看的是
TLS 握手 / HTTP2 的**指纹**（密码套件顺序、扩展、伪头顺序……），这些由客户端库
决定，改 User-Agent 一点用都没有 —— 项目里做过对照：换成完整浏览器请求头依旧 403。

所以 v1.0.0 的做法是：**让请求本身来自一个真浏览器的指纹**（`curl_cffi` +
`libcurl-impersonate`，已打进 EXE），过不去再按路线一那张表逐级升级。

- 程序**不会**读你的浏览器 Cookie 去做别的事：L2 的凭据来自**程序自己新开的**临时浏览器会话，
  只用于同一个站点，日志与诊断信息里对 cookie 一类响应头做了白名单过滤；
- 程序**不会**答题、不会调用打码服务、不会伪造 `cf_clearance`；
- 站点的风控会变，也可能因为出口网络"像机房"而更严格（**主因是指纹不是 IP**：
  同一个出口、同一分钟，裸请求 403、换指纹 200，项目里做过这个对照），
  所以也可能出现"今天一层就过、明天要多升一层"的情况 —— 那是风控在变，不是程序坏了。

如果四层都没过，报错里会写清"是哪几层试过了"，并保留路线二（你自己在浏览器里
通过验证 → 另存网页 → 导入）作为兜底。

## 9. 从源码运行 / 测试 / 重新打包

以下命令都在 **`source/`** 目录里执行（需要自备 Python 3.11+ 64 位）：

```bat
:: 安装运行依赖
python -m pip install -r requirements.txt

:: 直接运行源码版
python khdownloader_gui.py

:: 跑全部测试（179 项，除少数"站点真连"用例会跳过外都是离线）
python -m unittest discover -s tests -p "test_*.py"

:: 过校验的三组对照验证（会真的访问站点，A 组故意用裸 requests 反证）
python tools\verify_cloudflare_bypass.py

:: 重新打包成 dist\KHDownloader.exe（走打包驱动）
python -m pip install pyinstaller
build_exe.bat

:: 打包并让产出的 EXE 真连一次站点自检
build_exe.bat --selftest
```

> 打包走的是 `tools\build_frozen.py`，不是直接调 PyInstaller。它多做三件事：
> ①环境里若躺着 `pathlib` 这类"标准库的过时 backport 包"，PyInstaller 会直接拒绝
> 构建，驱动会在构建期间临时把它挪开、结束后原样还原（**不动你的 Python 环境**）；
> ②构建完**开包验收** `curl_cffi` 与 `libcurl` 是否真的在包里 —— 少了它程序会静默
> 退回普通请求，用户看到的还是"被拦住"；③`--selftest` 会让产出的 EXE 自己连一次
> 站点，用退出码和报告说话（EXE 没有控制台，只能这样自证）。
> 重新打包需要 `source\assets\` 下的两个图标文件存在，否则脚本会直接报错停止 ——
> 不会产出"看着像有图标、实际还是默认图标"的程序。

## 10. 合规说明

- 本工具用于下载你**有权下载和使用**的内容，供个人学习与研究；
- **不**实现任何绕过登录、绕过付费、破解验证码（含打码接口）、伪造 `cf_clearance`
  或复用他人会话的手段。v1.0.0 的"换浏览器指纹"是让请求**以真浏览器的方式**去读一张
  任何人都能打开的公开专辑页，等价于把浏览器本身当客户端用；
- 需要浏览器时，L3 用内置内核开一个**全新的临时会话**，L4 用**一次性临时配置目录**跑
  本机浏览器 —— 都不读你的浏览器配置、书签、历史或 Cookie；
- 除了你选择的下载目录和系统临时目录，不在别处产生文件；
- 不采集任何凭据或个人信息；诊断日志里对 cookie / 认证类响应头做了白名单过滤。

## 11. 已知限制

- 只支持 MP3，不支持 FLAC；
- 一次一张专辑、顺序下载，不支持并发 / 队列；
- **没有断点续传**：取消后重新开始，未完成的那首会从头下（已下好的会跳过）；
- 取消是**协作式**的：点取消后要等当前一小块数据落盘才停（不会损坏文件）；
- 没有失败自动重试；
- **不支持 MHTML / `.mht`** 网页归档，只能导入 `.html/.htm`；
- 过站点校验的四层里，L2 / L3 需要源码版装了 Playwright；**EXE 里只有 L1 和 L4**
  （L4 需要你机器上有 Chrome 或 Edge，通常都有）；
- 站点风控在变、出口 IP 也在变，所以**没有人能承诺"永远一次就过"**；
  四层都没过时程序会说明是哪几层试过了，并保留"导入网页"这条兜底路线。
