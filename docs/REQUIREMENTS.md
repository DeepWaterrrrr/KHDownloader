## 1. 项目背景

用户正在学习 Python，希望通过一个**真实有用的小工具**来练习，而不是做练习题。
工具的目标：把一个 KHInsider 的专辑页面地址丢进去，让它自动把这张专辑的 MP3
下载到本地指定文件夹，全程有界面、有进度、有看得懂的日志。

因此有两个目标同时存在：

- **能用**：确实能把专辑下载下来；
- **能看懂**：代码结构要清晰到"一个正在学 Python 的人能逐段读懂并自己改"。

第二个目标和技术先进性冲突时，**选可读性**。

## 2. 功能需求

### 2.1 界面（GUI）

桌面图形界面，包含：

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| G1 | 专辑地址输入框 | 用户粘贴 KHInsider 专辑页地址；使用前去掉首尾空白 |
| G2 | 保存目录输入框 | 可以手动填，也可以点按钮选；选过的目录在本次会话内保留 |
| G3 | 文件夹选择按钮 | 弹系统文件夹选择框 |
| G4 | 开始下载按钮 | 一次只跑一张专辑；**运行中禁用**，防止重复启动 |
| G5 | 专辑级进度条 | determinate：显示"整张专辑下到第几首了"（`n / N`）与**当前曲名** |
| G6 | 当前文件进度 | 有 `Content-Length` 时显示字节 / 百分比；**没有时不编造百分比**，改为不确定态 |
| G7 | 可滚动的日志区 | 分得清"解析专辑 / 解析曲目页 / 正在下载 / 跳过 / 完成 / 失败 / 取消" |
| G8 | 明确的结束/出错反馈 | 结束时有**分类汇总**（完成 / 跳过 / 失败 / 取消）；出错弹人话提示 |
| G9 | 取消按钮 | 协作式取消：在"两首之间 / 两块之间"安全停下；删掉未完成的临时文件；已下好的文件不动 |

> G5/G6 在 v004 中由"一条总进度条"细化为**专辑级 + 当前文件级两条**，
> 并新增 G9（取消）。这是为了让界面能真实、诚实地反映"整张下到哪了"和"当前文件下到哪了"
> —— 属于需求澄清，不是为迁就实现而改需求。

### 2.2 下载流程

1. 打开专辑页；
2. 找出页面上的曲目链接（按页面顺序）；
3. 逐个打开曲目页；
4. 在曲目页上找到真正的 MP3 地址；
5. 把文件下载到用户选的文件夹。

- 目标格式：**只做 MP3**（本阶段不做 FLAC）；
- 一次一张专辑，**顺序下载**，不做并发；
- 下载过程中界面必须保持可操作，不能"卡死"；
- 用户可以随时点**取消**：取消后不再开新曲目、删掉未完成的临时文件、保留已下好的文件。

## 3. 质量要求

| 编号 | 要求 |
| --- | --- |
| Q1 | 代码分段清晰、有中文注释，新手能读懂 |
| Q2 | 依赖尽量少，不引入新手需要额外学习的框架 |
| Q3 | 网络超时、HTTP 错误、空输入等常见问题都要有**人能看懂**的提示，不能甩原始报错堆栈 |
| Q4 | 单首曲目失败不能拖垮整张专辑 |
| Q5 | 不覆盖已有的下载文件；重名要有确定、可预期的处理规则 |
| Q6 | 下载失败时不能把没下完的半成品当成"已完成"的文件留在硬盘上 |
| Q7 | 对站点保持礼貌：顺序请求、不轰炸、不并发 |
| Q8 | 文件名要能安全地落在 Windows 上（非法字符、保留设备名、路径过长） |
| Q9 | 进度显示必须诚实：拿不到总大小时显示"未知"，**不编造百分比** |
| Q10 | 结束汇总必须分得清"完成 / 跳过 / 失败 / 取消"；**有失败时不许说"全部完成"** |

## 4. 边界与合规

- 工具用于用户**有权下载和使用**的内容，供个人学习与研究使用；
- **不做**：破解或代答人机校验题、接入打码/识别服务、伪造 `cf_clearance`、
  复用他人会话或凭据、绕过登录或付费墙、绕过限流（本项目对站点始终顺序、低频请求）；
- 不引入 DRM 或访问控制规避行为；
- 需要浏览器时：L3 开**全新临时会话**，L4 用**一次性临时配置目录**
  （`--user-data-dir=<TemporaryDirectory>`）—— **不读**用户浏览器的配置、书签、历史、Cookie；
- 除了"用户选择的下载目录"和"项目自身的文件"，不产生其他外部副作用；
- 不采集任何凭据或个人信息；诊断日志对 cookie / 认证类响应头做白名单过滤。

> **v1.0.0 口径修订（2026-10-15，用户指令"帮我解决防火墙的问题"）**：
> 旧版写过"不实现任何绕过人机校验的手段"。经实测确认，站点判定的是 **TLS/HTTP2 客户端指纹**
> （请求头、Cookie、Referer、频率、代理均已排除），因此 v1.0.0 起程序的请求改用
> **与真浏览器一致的网络指纹**（`curl_cffi` + `libcurl-impersonate`），失败时逐级升级到
> 内置无头浏览器 / 本机浏览器。
> 这不属于上一条"不做"列表里的任何一项：它是**以真浏览器的方式读取任何人可访问的公开页面**，
> 没有破解校验、没有伪造令牌、没有借用他人身份。旧措辞见 `防火墙问题说明.md` §0–§7，
> 新立场见 `REPORT_v1.0.0_防火墙修复.md` §3.1。

## 5. 本阶段明确不做的事（非目标）

手工下载能做的"锦上添花"功能，本阶段都不做：

- FLAC 或其他格式下载；
- 全站爬取、专辑搜索、多专辑排队；
- 并发/多线程下载曲目；
- 暂停/续传；
- 下载记录数据库；
- 账号登录自动化；
- 验证码 / 人机校验 / 访问控制绕过；
- 代理轮换；
- 浏览器自动化（Selenium / Playwright）；
- 界面主题美化；
- 专辑封面下载；
- MP3 标签（ID3）编辑；
- 打包成 `.exe`；
- 自动更新；
- 生成播放列表；
- 失败重试风暴或高频请求。

这些以后想做可以再做，本阶段只是**先不做**，不是"永远不做"。

## 6. 验收标准（本阶段）

1. 打开程序能出现完整界面，控件齐全（G1–G9）；
2. 下载过程中界面不卡死；
3. 输入为空时有明确提示；
4. 单首失败不影响其他曲目，且错误可读；
5. 下载完成的文件是通过"先写临时文件、再改名"的安全方式落盘的；
6. 磁盘上不会留下"半成品顶着 .mp3 名字"的文件；
7. 重名文件有确定的处理规则，且不覆盖已有文件；
8. 至少有一条失败路径被真实测试过；
9. **取消能真正停下**：不留下未完成的 `.mp3`，已下好的文件完好；
10. **进度诚实**：缺 `Content-Length` 时不显示编造的百分比；
11. **汇总不误导**：有失败时不能显示"全部完成"。
