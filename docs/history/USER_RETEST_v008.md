# USER_RETEST_v008.md — v008 用户复测说明

> 本轮修复的问题：**导入的网页和地址框里的地址不是同一张专辑时，程序误报"没有曲目"**。
> 你不需要 Cookie、HAR 或任何凭据。

---

## 0. 运行哪个文件

**`KHDownloader.exe`**（就在本文件夹根目录，和本说明文件放在一起）。

- 双击即可，**不需要安装 Python**，也不需要装任何库。
- 文件名不带 `_v008` 之类的阶段编号 —— 这是当前唯一的正式入口。
- 大小与 SHA-256 见 `_MANIFEST.json` 与执行报告。

> 历史版本都还留着，只是不该再点：
> - 项目 `release\history\` 下是更早版本的归档，**不需要打开**；
> - 本文件夹里的 `KHDownloader.exe` 才是最新那个（已内置新图标）。

## 1. 复测场景 A：2003 HTML + 错误地址（你上一轮遇到的场景）

1. 地址框**故意**填 2011 那张专辑的地址
   （`…/album/cross-channel-in-memory-of-all-people-special-soundtrack-2011`）。
2. 点 **导入专辑页面…**，选择你保存的
   `CROSS†CHANNEL Soundtrack Arrange Version CRISS†CROSS (2003)….html`。
3. **预期**：弹出提示"地址框里的专辑与导入的网页**不是同一张专辑**"，
   并分别列出两个地址 —— **不再报"没有解析到任何曲目链接"**。
4. 点「是」（使用网页中的专辑地址）→ 地址框自动变成 2003 专辑地址 →
   弹出**曲目预览**：19 首、首曲 `Airwaves Arr.ver.`、末曲 `_and then_`。
5. 点「否」→ 什么都不下载，地址框保持原样。

## 2. 复测场景 B：空地址导入

1. 清空地址框 → 点 **导入专辑页面…** → 选同一个 2003 HTML。
2. **预期**：提示"已识别出专辑"，显示识别出的 2003 地址；点「是」回填 → 预览 19 首。

## 3. 复测场景 C：主动开始下载

1. 在预览框点「是」→ 立即开始下载，主窗口显示
   `来源：已导入网页（<2003 专辑地址>）`，曲目进度 0/19。
2. 保存目录就是你选的文件夹；中途可点 **取消**，已下好的保留、无 `.part` 残留。

## 4. 复测场景 D：保存网页指引

1. 点 **保存网页指引**：地址为空时给通用步骤；填了专辑地址时给完整四步
   （浏览器打开 → 等曲目列表出现 → `Ctrl+S` 另存为「网页，仅 HTML」→ 回来导入）。
2. 若浏览器保存成 `.mht/.mhtml`（单个文件），导入时程序会明确说这个格式不支持 ——
   这是有意为之，**改扩展名没有用**，请重新另存为「网页，仅 HTML」。

## 5. 复测场景 E：新图标（本轮新增）

1. 在**文件管理器**里看 `KHDownloader.exe`：应是**蓝色圆角方块 + 白色音符与下载箭头**。
2. 双击打开：窗口**标题栏左上角**和**任务栏**应是同一个图标。
3. 说明：如果你在同一个目录里看到旧图标，多半是 Windows 图标缓存。
   先把 EXE 复制到**另一个空文件夹**再看一次；仍显示旧图标再考虑重启资源管理器
   （`任务管理器 → 资源管理器 → 重新启动`）。**不需要**清理系统缓存或改注册表。

## 6. 失败时返回什么

把程序**"状态 / 日志"框的文本**复制回来（已脱敏，无 Cookie），再加一句话说明：
用的哪个场景（A/B/C/D/E）、卡在哪一步、弹窗标题是什么。

## 已知限制（如实说）

- 导入只解决"曲目发现"；详情页 / 音频主机若被拦，仍会按 v007 分类提示。
- "直接粘贴专辑 URL → 开始下载"仍可能被 Cloudflare 拦 —— 这是 v007 已知边界，本轮不变。
- 图标检查已覆盖 EXE 资源表、窗口标题栏、资源管理器取图三处；
  **但这些检查是在执行环境做的，不覆盖你的 Windows 图标缓存状态**。
- 本 EXE **没有数字签名**，首次运行 Windows 可能提示"Windows 已保护你的电脑"
  → 点「更多信息」→「仍要运行」。
- 已在执行环境用你的**原样 2003 / 2011 HTML** 实跑通过（19 首 / 30 首）；
  剩下的就是你自己手点一遍确认。
